# WEEK 11 - Email Agents & Safety Guardrails
Week 11 extends the multi-agent real-estate assistant with an email communication workflow and explicit safety guardrails.

The email agent allows property-search results, listing alerts, market reports, and personalized property recommendations to be prepared as email drafts and sent to a user.

A human-in-the-loop approval workflow is enforced before any email can be sent. The system first generates an email draft and displays a preview through WhatsApp. The user must explicitly approve the draft before the email service is allowed to send it.

This ensures that outbound communication remains under user control and prevents autonomous email sending.

## Nodemailer Installation
Week 11 uses Nodemailer to send approved emails through Gmail.

## Email Credentials Configuration
Email credentials are stored using environment variables rather than hard-coded inside the application.

Example:
```env
EMAIL_USER=your-email@gmail.com
EMAIL_PASSWORD=your-google-app-password
```
`EMAIL_PASSWORD` should contain the Gmail App Password used by the application rather than a normal account password.(Shown below)

>**Note:** The `.env` file is excluded from Git and should never be committed to the repository.

## Files
### 1. `email.ts`
The `email.ts` service provides the low-level email functionality.
Nodemailer is used to send approved emails through Gmail.

Features include:
- Gmail SMTP transport
- Environment-variable credential loading
- Recipient validation
- Email draft creation
- Unique draft IDs
- Draft status tracking
- Explicit approval validation
- Test transport injection
- Protection against unauthorized email sending

The email service does not allow a draft to be sent unless its status is explicitly set to `approved`

If the email is still `pending_approval` the send operation is rejected.

### 2. `week11Skill.ts`
The Week 11 skill manages the complete email workflow.

Responsibilities include:
- Detecting the requested email type
- Extracting recipient email addresses
- Requesting a recipient when one is missing
- Remembering pending email conversations
- Generating property-summary emails
- Generating listing-alert emails
- Generating market-report emails
- Generating recommendation-digest emails
- Creating email previews
- Storing pending drafts in the user session
- Processing approval commands
- Processing cancellation commands
- Calling the protected email service after approval

Supported draft purposes are:
- listing_alert
- market_report
- property_summary
- recommendation_digest

Unknown email requests are not automatically converted into property-summary emails.

For example:
```text
Email me the answer to what is DOM
```
does not silently reuse previous property results.

Instead, the user is informed of the supported email types.

### 3. `intentClassifier.ts`
The intent classifier was extended to support Week 11 email conversations.

The classifier distinguishes between:
- Email-only requests
- Property search + email
- Recommendation + email
- Email approval commands
- Email cancellation commands
- Recipient follow-up messages
- Email-purpose follow-up messages

Example:
```text
Email property results to user@example.com
```
is classified as `email`

while:
```text
Find homes in Irvine and email me the results
```
is classified as `search + email`

and:
```text
Find similar homes and email them to user@example.com
```
is classified as `recommend + email`

### 4. `orchestrator.ts`
The Week 9 orchestrator was extended to coordinate email workflows.
Email agents may depend on results generated by other agents.
For example:
```text
Find similar homes and email them
```

requires:
```text
recommendationAgent
        ↓
Week 7 Recommendation Engine
        ↓
Store Recommendation Results
        ↓
emailDraftAgent
```

Therefore, email execution occurs after the agent responsible for generating the email content.
This prevents the email agent from reading stale property-search results before recommendation generation is complete.

### 1. `photos.ts`
The photo utility validates MLS media before it is included in property emails.
The `L_Photos` field may contain multiple media URLs, including non-image media or expired media records.

The utility:
- Parses `L_Photos` defensively
- Supports string and object media entries
- Rejects PDF/document URLs
- Accepts recognized image formats
- Recognizes Trestle `PHOTO-Jpeg` media URLs
- Validates remote image availability
- Rejects unavailable or expired media URLs
- Prevents broken media from being inserted into email HTML

This helps ensure that property-summary and listing-alert emails display valid property images whenever available.

## Email Safety Flow - Safety Guardrails  
The most important Week 11 requirement is the explicit approval gate.
The system follows this workflow:

```mermaid
flowchart TD

A[Email Request]

A --> B[Create Draft]

B --> C[pending_approval]

C --> D[WhatsApp Preview]

D --> E{User Decision}

E -->|Approve| F[approved]

E -->|Cancel| G[Draft Removed]

F --> H[sendApprovedEmail]

H --> I{Safety Check}

I -->|Approved| J[Send Email]

I -->|Not Approved| K[Block Send]
```

## Approval Workflow
When an email is prepared, the user receives a preview similar to:
```text
📧 Email Draft

To: user@example.com
Subject: Property Search Results
Purpose: Property Summary
Status: pending_approval

Preview:
...

No email has been sent.

Reply "approve email" to send it.
Reply "cancel email" to discard it.
```

The user can approve using:
- approve
- approve email

The user can cancel using:
- cancel
- cancel email

If approved successfully:
```text
✅ Email sent successfully.

To: user@example.com
Subject: Property Search Results
```

## Email Agent Integration
The Week 11 email agent is integrated into the existing Week 9 multi-agent orchestration system and Week 10 WhatsApp communication layer.
Users can request emails directly through WhatsApp. The intent classifier identifies the email request and routes it to the `emailDraftAgent`.
The email agent delegates the request to `week11Skill.ts`, which determines the requested email type, retrieves the required data from the existing property-search, market-analytics, or recommendation workflows, and generates an email draft.
The draft is stored in the user's session with a `pending_approval` status.
No email is sent at this stage.
The draft is displayed to the user through WhatsApp, and the user must explicitly reply with an approval command before the email can be sent.

## Supported Email Workflows
Week 11 supports the following real-estate email workflows:

### 1. New Listing Alerts
New listing alerts use the user's existing property-search results and preferences to prepare an email containing matching active listings from `rets_property`.

Example:
```text
Find 3 bedroom condos in Irvine under $1M
```

Followed by:
```text
Email me new listing alerts to user@example.com
```

### 2. Weekly Market Reports
Market-report emails reuse the Week 5 market-analytics pipeline.
Market data is generated from `california_sold` and may include:
- Sold comparable count
- Median close price
- Average close price
- Average price per square foot
- Average days on market
- List-to-close ratio
- Active inventory
- Active-to-sold ratio
- Monthly price trends
- Market narrative

Example:
```text
Email market report for Irvine to user@example.com
```

### 3. Property Summary
Property-summary emails use the results from the user's most recent property search.
The email includes information such as:
- Property address
- Listing price
- Bedrooms
- Bathrooms
- Square footage
- HOA information
- Days on market
- Property remarks
- Property photos when valid media URLs are available

Example:
```text
Find 3 bedroom condos in Irvine under $1M and Email me the property results to user@example.com
```

### 4. Personalized Recommendation Digest
Recommendation-digest emails integrate with the Week 7 recommendation engine.
The recommendation agent first generates similar properties and stores the ranked recommendation results in the user's session.
The email agent then runs after the recommendation agent so that the email contains the actual Week 7 recommendation results rather than the original property-search results.

Example:
```text
Find 3 bedroom homes in San Diego under $1.5M
```

Followed by:
```text
Find similar homes and email to user@example.com
```
